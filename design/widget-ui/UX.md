## 화면 구조 (모든 상태 공통)

위젯은 380 × 560px iframe 안에 세 칸으로 나뉩니다.

1. **헤더 (고정):** 아바타 "L" · 제목 · 부제 · 닫기(✕, `notifyClose`)
   - 기본 제목 "피드백 보내기", 부제 "{reporter.name} 님 · 보통 1영업일 안에 답변드려요"
   - reporter가 없으면 부제는 "보통 1영업일 안에 답변드려요"만 표시
2. **대화 영역 (스크롤):** 안내 말풍선, 유형 칩, 안내 배너, **첨부 카드 목록**
   - 첨부가 많아져도 이 영역만 스크롤되고 아래 입력부는 움직이지 않습니다.
3. **입력부 (고정):** 도구 4개 → 입력창 + 보내기 → 힌트 줄

## 상태별 화면

코드의 상태 값과 시안 번호를 짝지었습니다. 위에서부터 먼저 맞는 것을 보여줍니다.

| 우선순위 | 코드 상태 | 시안 | 보여줄 것 |
|---|---|---|---|
| 1 | `bridgeErrorMessage` 있음 | ⑫ | 열 수 없음 안내 + 개발자용 원인 상자. 입력부 대신 닫기 버튼 |
| 2 | `!isInitialized` | ⑪ | 준비 중 뼈대, 도구·입력·보내기 잠금 |
| 3 | `status === 'success'` | ③ | 완료 화면 |
| 4 | `captureState.activeMode === 'comment'`, `selection` 없음 | ④ | 요소 고르기 안내 + 취소 |
| 5 | `activeMode === 'comment'`, `selection` 있음 | ⑤ | 선택 요소 이름표 + 코멘트 입력 |
| 6 | `activeMode === 'edit'` | ⑥ | 끌어 옮기기 안내 + 취소 |
| 7 | `activeMode === 'flow'` | ⑦ | 기록 중 배너 + 글 지워짐 경고 + 기록 종료/취소 |
| 8 | `status === 'submitting'` 또는 `screens.status !== 'idle'` | ⑩ | 진행 문구, 입력·보내기 잠금 |
| 9 | `status === 'error'` | ⑨ | 입력 내용 유지 + 오류 배너 |
| 10 | 그 외 | ①·②·⑬ | 기본 작성 화면 |

- `captureState.enabled === false`이면 기본 작성 화면에 ⑧처럼 도구를 흐리게 하고 경고 배너를 띄웁니다.
- 첨부가 1개 이상인데 본문(`message.trim()`)이 비어 있으면 ⑬처럼 힌트 줄 왼쪽을 primary 색 **"한 줄이라도 내용을 적으면 보낼 수 있어요"** 로 바꿉니다. 보내기 조건(`canSubmit`)은 바꾸지 않습니다.
- 코멘트 첨부나 위치 편집이 끝나면 위치 표시용 화면이 자동 저장되어(`captureForMarks`) 잠깐 ⑩ 상태가 됩니다. 이때 보내기가 잠기는 것은 정상입니다.

### ①·② 기본 작성 화면

- **유형 칩:** 기존 `<select>`를 칩 4개로 바꿉니다.
  - 순서: 버그 · 개선 제안 · 질문 · 기타 (값은 `FEEDBACK_TYPE_OPTIONS` 그대로, 기본값 `bug`)
  - `role="radiogroup"` + 각 칩 `role="radio"` / `aria-checked`, 또는 `aria-pressed` 버튼. 하나만 선택됩니다.
  - 칩은 인사 말풍선 안에 둡니다. 말풍선 문구는 아래 "문구" 표를 따릅니다.
- **도구 4개** (한 줄 4칸, 아이콘 위·이름 아래)

| 도구 | 누르면 | 비활성 조건 |
|---|---|---|
| 요소 코멘트 | `capture:start` comment | `!enabled`, 다른 모드 진행 중, 개수 한도 |
| 위치 편집 | `capture:start` edit | 같음 |
| 흐름 기록 | `capture:start` flow | 같음, 이미 흐름 1개 있음 |
| 화면 저장 | `screens.capture` | `!screens.canCapture`, 저장·전송 중 |

  - 첨부가 하나라도 있으면 각 도구 아래에 사용 개수를 `1/20`처럼 작게 표시합니다. 한도는 `MAX_COMMENTS`, `MAX_EDITS`, 흐름 1, `MAX_SCREEN_SNAPSHOTS_PER_FEEDBACK`에서 읽습니다. 숫자를 하드코딩하지 않습니다.
  - 한도에 걸려 비활성일 때는 기존 `findStartBlocker` 문구를 `title`과 스크린리더용 텍스트로 제공합니다.
- **첨부 카드 목록:** 대화 영역 아래쪽에 "첨부한 화면 정보 N개 · 보낼 때 함께 전달돼요" 제목과 함께 표시합니다.
  - 순서: 코멘트 → 위치 편집 → 흐름 → 저장한 화면
  - 카드 = 아이콘 칸 + 굵은 제목 + 한 줄 설명(넘치면 말줄임) + 삭제(✕, 36px 이상, `aria-label="{제목} 삭제"`)
  - 카드 제목과 설명은 기존 요약 함수를 그대로 씁니다(`getTargetLabel`, `getEditSummary`, `renderFlowSummary`, `getSnapshotSummary`).
  - 자동 저장 화면(`markedScreenIds`에 들어 있는 화면)은 제목을 "저장한 화면 {n} · 코멘트 위치 포함"(편집이면 "편집 위치 포함", 둘 다면 "코멘트·편집 위치 포함")으로, 설명 앞에 "코멘트를 달 때 자동으로 저장됐어요"를 붙입니다. 구분이 어렵다면 기존처럼 "코멘트·편집 위치 포함" 하나로 통일해도 됩니다.
  - 흐름 재생 화면(`flowScreenIds`)은 제목 "저장한 화면 {n} · 흐름 재생", 설명 앞에 "흐름 기록을 마칠 때 자동으로 저장됐어요". 뒷부분이 잘린 재생(`truncatedFlowScreenIds`)은 "흐름 재생(뒷부분 잘림)".
  - 흐름 카드를 삭제하면 흐름 재생 화면 카드도 함께 사라집니다(`removeFlowScreens`, 이미 구현됨). 사용자가 놀라지 않도록 흐름 카드의 삭제 버튼 `aria-label`을 "흐름 기록과 재생 화면 삭제"로 합니다.
  - `truncatedFlowScreenIds`가 있으면 첨부 목록 위에 노란 배너(⑧과 같은 모양)로 잘림 안내를 띄웁니다(문구는 "말투 통일" 표).
  - 기존 "코멘트 0/20 · 위치 편집 0/10 · 흐름 0/1" 한 줄 요약은 도구 아래 개수로 대체하므로 지웁니다.
- **입력창:** placeholder "어떤 점이 불편하셨나요?", 2줄 높이에서 최대 4줄까지 늘어남. 오른쪽에 정사각형 보내기 버튼(아이콘 + `aria-label="보내기"`).
  - 힌트 줄: 왼쪽 "Enter 줄바꿈 · ⌘+Enter 보내기", 오른쪽 `{글자 수}/5000`
  - ⌘+Enter(Windows는 Ctrl+Enter)로 보내기는 **있으면 좋은 기능**입니다. 시간이 없으면 힌트 문구와 함께 뺍니다.
- **화면 저장 안내문:** 기존 `STATUS_MESSAGES.idle` 문구는 도구 버튼의 `title`로 옮기고, 화면에는 상시로 띄우지 않습니다.

- 요약 카드(`result.feedback` 기준): 유형 라벨 / 페이지(`page.title`) / 첨부 요약(예: "코멘트 1 · 흐름 기록 · 화면 1", 없으면 "없음")
- 버튼 두 개: "닫기"(`notifyClose`) · **"다른 피드백 작성"**(기존 `handleWriteAnother`, 강조)

### ④ 요소 코멘트 · 고르는 중

- 헤더 제목 "요소 코멘트", 부제 "Esc 키로도 취소할 수 있어요"
- 파란 배너: **"페이지에서 요소를 클릭하세요"** / "마우스를 올리면 파란 테두리가 보여요. 클릭해도 원래 버튼은 실행되지 않아요."
- 입력부에는 "요소 코멘트 취소" 버튼 하나만(`capture:cancel`).

### ⑤ 요소 코멘트 · 의견 쓰기

- 헤더 왼쪽 ✕ 대신 뒤로(←) 버튼 = 취소. 부제는 "코멘트 {현재 개수+1}/{MAX_COMMENTS}"
- 배너: "요소를 골랐어요" + 선택 요소 이름표(고정폭 글꼴, `getTargetLabel(selection)`)
- 입력창(자동 포커스, 3줄), 힌트 "이 요소에 대한 의견" · `{글자 수}/{MAX_COMMENT_LENGTH}`
- 버튼: "취소" · **"코멘트 첨부"**(기존 `handleAttachComment`, 내용 없으면 비활성)

### ⑥ 위치 편집

- 헤더 제목 "위치 편집", 부제 "위치 편집 {개수+1}/{MAX_EDITS}"
- 배너: **"요소를 원하는 곳으로 끌어 놓으세요"** / "다 옮겼으면 페이지 위의 **변경 첨부** 버튼을 눌러 주세요. 미리보기일 뿐이라 실제 화면과 데이터는 바뀌지 않아요."
  - "변경 첨부" 확정 버튼은 SDK 오버레이(`src/sdk/element-drag.ts`)에 있으므로 위젯에는 만들지 않습니다.
- 입력부: "위치 편집 취소" 버튼 하나.
- 시안의 "옮긴 거리" 카드는 지금 state로 실시간 값을 받을 수 없으면 생략합니다.

### ⑦ 흐름 기록 중

- 헤더 제목 "흐름 기록", 부제 "평소처럼 페이지를 사용하세요 · 최대 {MAX_REPLAY_DURATION_MS를 분으로}분"
- 빨간 배너: 깜박이는 빨간 점 + **"기록 중"** / "클릭, 화면 이동과 화면 변화를 기록해 담당자가 그대로 재생해 볼 수 있어요. **입력한 값은 가려서 저장해요.**"
  - 기존 `MODE_STATUS.flow`(PR #19에서 바뀐 긴 문구)는 이 배너로 대체합니다. 기록을 마치면 흐름 재생 화면이 자동 첨부된다는 사실은 ②의 카드로 보여주므로 배너에서는 뺍니다.
  - 시안의 경과 시간(00:24)은 위젯이 시작 시각을 알 수 있을 때만 표시합니다. 없으면 "기록 중"만.
  - 깜박임은 `prefers-reduced-motion: reduce`일 때 끕니다.
- 그 아래 노란 배너(항상 표시): "다른 페이지로 이동하면 **작성 중이던 글이 지워질 수 있어요.** 기록을 마친 뒤 글을 써 주세요."
  - 이유: Flow는 새로고침·문서 이동 후에도 이어지지만 본문·코멘트 초안은 복원되지 않습니다(README 2절). 나중에 초안 복원이 생기면 이 배너를 지웁니다.
- 버튼: "기록 취소"(`capture:cancel`) · **"기록 종료 및 첨부"**(빨간 배경, `flow:stop`)

### ⑧ 화면 첨부가 허용되지 않은 페이지 (`captureState.enabled === false`)

- 도구 4개를 숨기지 않고 비활성(흐리게) 처리합니다.
- 입력부 위에 노란 배너: "이 페이지에서는 화면 첨부를 쓸 수 없어요. 글로만 보내도 괜찮아요."
- 화면 저장도 `canCapture`가 거짓이면 함께 비활성.

### ⑨ 전송 실패 (`status === 'error'`)

- 쓴 내용, 유형, 첨부를 **지우지 않습니다.**
- 입력부 위에 빨간 배너(`role="alert"`): **"전송하지 못했어요"** / 서버 오류 문구(`errorMessage`)가 있으면 그 문구, 없으면 "잠시 후 다시 시도해 주세요. 작성한 내용은 그대로 남아 있어요."
- 보내기 버튼은 다시 누를 수 있어야 합니다(같은 제출 함수 재호출).
- 시안처럼 보낸 내용을 내 말풍선으로 미리 보여주는 것은 선택입니다. 어렵다면 입력창을 그대로 두고 배너만 띄웁니다.
- `captureState.errorMessage`와 `screens.errorMessage`도 같은 빨간 배너 모양으로 보여줍니다.

### ⑩ 전송 중 · 화면 저장 중

- 보내기 버튼과 입력창 잠금(중복 전송 방지)
- 파란 배너 문구
  - `screens.status === 'capturing'`: "화면을 저장하는 중이에요…"
  - `screens.status === 'uploading'`: "저장한 화면을 올리는 중이에요…"
  - `status === 'submitting'`: "보내는 중이에요…"

### ⑪ 준비 중 (`!isInitialized`)

- 헤더 부제 "준비하는 중이에요…"
- 대화 영역에 회색 뼈대 막대 3줄(은은한 반짝임, `prefers-reduced-motion`이면 정지), `role="status"`
- 도구 4개·입력창·보내기 모두 비활성. 지금 코드처럼 화면 저장 컨트롤을 아예 숨기지 말고 같은 자리에 비활성으로 둡니다(준비가 끝났을 때 화면이 덜컹거리지 않게).

### ⑫ 위젯을 열 수 없음 (`bridgeErrorMessage`)

- 빨간 배너: **"피드백 창을 열 수 없어요"** / "페이지를 새로고침해 주세요. 계속 이러면 래티스 담당자에게 알려 주세요."
- 아래 회색 고정폭 상자: "원인(개발자용): {bridgeErrorMessage}"
- 입력부 대신 "닫기" 버튼 하나.

## 문구

말투는 "~해요"체로 통일합니다. 기술 용어(DOM, selector, iframe)는 화면에 쓰지 않습니다.

| 위치 | 문구 |
|---|---|
| 인사 말풍선 | "안녕하세요, {이름} 님 👋" / "불편한 점을 편하게 적어 주세요. 글로 설명하기 어려우면 아래 도구로 **화면에서 직접** 보여주셔도 돼요." |
| 인사 말풍선 (이름 없음) | "안녕하세요 👋" + 같은 둘째 문장 |
| 도구 영역 제목 | "화면으로 보여주기 (선택)" |
| 첨부 목록 제목 | "첨부한 화면 정보 {N}개" · "보낼 때 함께 전달돼요" |
| 코멘트 카드 | 제목 "코멘트 {n}", 설명 "{요소 이름} · {코멘트}" |
| 위치 편집 카드 | 제목 "위치 편집 {n}", 설명 `getEditSummary` 결과 |
| 흐름 카드 | 제목 "흐름 기록 · 이벤트 {N}개", 설명 "클릭 → 입력 → …" |
| 화면 카드 | 제목 "저장한 화면 {n}", 설명 "{가로}×{세로} · {시각}" (+ 누락 있으면 " · 글꼴·이미지 {N}개 누락") |

## 접근성

- 모든 아이콘 버튼에 `aria-label`
- 진행·안내 배너는 `role="status"` + `aria-live="polite"`, 오류는 `role="alert"`
- 키보드로 모든 버튼에 이동 가능, 포커스 링은 primary 색 2px
- 글자와 배경 대비 4.5:1 이상 (muted 색은 개수·힌트에만 사용)
