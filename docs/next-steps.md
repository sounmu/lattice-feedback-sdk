## 이번 작업 티켓 초안: Supabase 영구 저장

- 담당: 메인 개발.
- 문제: 현재 저장 데이터가 서버 재시작이나 다른 인스턴스에서 유지되지 않는다.
- 범위: DB 스키마, 기존 `FeedbackRepository`의 Supabase 구현, 설정과 실패 응답, 테스트.
- API 계약: 기존 JSON 응답·관리자 인증·프로젝트별 조회 조건을 유지한다.
- 제외: 관리자 UI, Supabase Auth 도입, 사용자 인증 모델 변경, 분산 rate limit.
- 설정 방법: `docs/supabase-setup.md`.
- 검증: 타입 검사, lint, 전체 테스트, build 및 실제 Supabase 대상 재시작·권한 확인.
- 협업: 기능과 관련 테스트를 하나의 PR로 묶는다. 300–400줄은 권장 크기이며 강제 상한이 아니다.
  로컬 타입 검사·lint·테스트·build와 해당 기능의 E2E를 통과한 뒤 통합 브랜치에 병합한다.
  커밋과 병합 결과는 원격에 push하고 병합된 작업 브랜치는 정리한다.
  main에 직접 커밋하거나 push하지 않는다.
